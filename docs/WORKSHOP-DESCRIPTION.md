# STS1 战斗求解器 / STS1 Engine Solver

STS1 战斗求解器是一个面向《杀戮尖塔 1》单人模式的战斗路线求解器。

进入战斗后，它会在后台把当前战斗镜像到一个隔离的沙盒副本中，让游戏自己的卡牌、遗物、药水与怪物代码在副本上真实运行，并在预算范围内搜索出一条从当前回合打到战斗结束的完整出牌路线。面板按回合展示每一步的出牌、目标与结果；你可以只看建议，也可以让它执行一步，或连续接管整场战斗。

## 主要功能

- **不重写卡牌**：求解器不维护任何卡牌效果表，直接调用游戏自身的结算代码，因此不存在"卡牌表与游戏不同步"的问题。
- **跨回合搜索**：不只算当前一回合，会继续预测抽牌、洗牌、敌人行动、能量与遗物触发。
- **清晰的路线面板**：每个回合一行，每个动作一行；每个动作都写明卡牌与目标，并给出该动作之后的敌人生命。
- **预计战损**：评分顺序为"先活下来、再赢、再少掉血、最后少用药水"，而不是只看当前回合伤害。
- **执行校验**：计划里记录每一步预测的状态摘要；实际执行后逐步比对，第一次不一致就作废整条路线并要求重算，不允许计划与游戏各说各话。
- **未展开即声明**：无法忠实复现的分支不会被猜测，而是在面板底部命名为"未展开"，避免给出一条错误的"最优解"。
- **药水策略**：可整体允许或禁止求解过程使用药水；开启后按可用药水数分档搜索（0 瓶到 n 瓶各一条世界线，净扣血优先、同样损失少喝一条），面板实时提示当前正在计算哪一档。
- **局外收益**：可选择是否把金币、最大生命、永久伤害、升级与药水计入评分。
- **三种使用方式**：仅查看路线、执行一步、自动出牌（按设定节奏连续执行至战斗结束）。
- **随时停止**：计算过程中再点一次"计算"即可停止；停止后不会在后台偷偷继续。
- **原生界面与动画**：开局选牌、回合开始选牌、抽弃牌等仍走游戏原生页面，不替换 UI。

## 使用方法

1. 安装并启用前置模组 **ModTheSpire** 与 **BaseMod**。
2. 启用本模组后进入一场单人战斗。
3. 等待发牌与回合开始效果结算，右上角会显示求解器面板。
4. 点击 **计算** 开始搜索；搜索完成后在面板中查看路线。
5. 需要执行时点击 **执行一步**，或打开 **自动出牌** 让它连续执行。
6. 可用 **秒数 / 节点** 调整搜索预算，用 **节奏** 调整自动出牌的间隔（默认 750 ms）。

## 原理与代码来源

本项目的架构参考了《杀戮尖塔 2》的 Combat Solver（作者 Torch，MIT 许可）：先抓取根状态，在后台模拟而不触碰实机战斗，打印路线，通过游戏原生入口执行，并在实际状态偏离时重算。原项目的路线模型与「执行时校验、偏离即重算」的思路对本项目有直接影响。

两者的实现机制必然不同：杀戮尖塔 1 的引擎是 Java 加大量进程级静态状态，因此这里的「后台模拟」是把克隆出来的战斗世界换进静态槽位，而不是另写一套规则。求解器不加载、也不分发任何第三方程序集。原项目的版权声明与许可全文随本项目源码一同保留，不改变其归属。感谢 Torch 与 Combat Solver 的工作。

## 依赖与兼容性

- 需要 **ModTheSpire 3.30.0 或更高版本** 与 **BaseMod**。
- 适配《杀戮尖塔 1》的最终版本（12-18-2022）。该游戏已停止更新，因此不另做版本分支适配。
- 仅支持单人战斗。
- 兼容性边界：求解器调用游戏自身代码，因此**理论上兼容所有只增加内容（卡牌、遗物、药水、角色、怪物、事件）而不改变战斗结算方式的 mod**。改写伤害计算、动作队列、回合结构或抽洗牌顺序的 mod 可能模拟结果与实机不一致。
- 已实测组合：原版，以及原版 + 菜农 mod。
- 模拟在副本上进行，实机战斗的随机数状态不受影响。

## 性能说明

- 搜索会占用较多 CPU 与内存；默认预算适合普通桌面配置，可按电脑性能调整"秒数"与"节点"。
- 搜索在游戏内后台进行，会周期性让出执行权，尽量降低对操作与动画的影响。
- 展示的是当前预算内找到的最佳路线，**不承诺数学意义上的全局最优解**。
- 参考读数：一场三回合战斗约 6193 个节点、40 秒完成计算。

## 问题反馈

- 反馈渠道：创意工坊留言，或在 GitHub 仓库提交 Issue。
- 建议附上诊断文件：面板标题行右侧的「导出报告」按钮会生成一个压缩包，包含日志、设置与版本信息，便于定位。
- 也可以手动附上日志：`%USERPROFILE%\sts1-engine-solver\solver.log`，并说明层数、角色、卡组与当时面板内容。

## 已知边界

- 依赖游戏内部结构，游戏本体或大型机制类 mod 更新后可能需要重新适配。
- 未展开的分支会在面板底部列出，这些分支上给出的路线不一定最优。
- 搜索受时间与节点预算限制，预算不足时路线质量会下降。
